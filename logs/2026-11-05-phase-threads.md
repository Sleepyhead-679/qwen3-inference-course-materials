# Qwen3 CPU 分阶段线程实验（2026-11-05）

## 配置与方法

模型为 Qwen3-0.6B Q8_0，SHA-256 为 `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031`。使用同一个 CPU 版 `llama-cli` 构建 `b11923-de5122d8`，比较固定配置 `-t 16 -tb 16` 与混合配置 `-t 8 -tb 16`。

固定输入见 [thread-compare.txt](../inputs/thread-compare.txt)，SHA-256 为 `271c4d2e9a90826ab932af178dea71798b225ccda75677ad54cb45dbd70675d5`。两组均使用 `-ngl 0 -b 2048 -ub 512 -c 2048 -n 128 -s 42 --temp 0 --ignore-eos --show-timings --simple-io -st`。交替运行 5 轮，每轮计算“混合配置速度 / 固定配置速度”，再取配对比值中位数。完整命令、原始输出和汇总见[正式实验目录](raw-phase-threads/20261105T121001Z-f03c87a5/)。

## 结果

| 轮次 | 固定配置生成 token/s | 混合配置生成 token/s | 生成速度比 |
| --- | ---: | ---: | ---: |
| 1 | 37.4 | 48.1 | 1.2861 |
| 2 | 39.2 | 48.4 | 1.2347 |
| 3 | 41.0 | 48.4 | 1.1805 |
| 4 | 41.1 | 48.3 | 1.1752 |
| 5 | 41.4 | 48.4 | 1.1691 |

固定配置与混合配置的生成速度中位数分别为 41.0 和 48.4 token/s；配对生成速度比中位数为 1.1805，即提升约 18.05%。5 轮配对结果均显示混合配置更快。

提示处理速度的配对比值中位数为 0.9821，逐轮波动明显。两组提示处理线程数均为 16，不能将读数差异归因于生成线程设置。本实验只测得两阶段吞吐率，尚未测量完整请求的端到端耗时或能耗。

## 结论

本机 Qwen3-0.6B Q8_0 的逐 token 生成采用 8 线程、提示处理采用 16 线程时，生成吞吐率高于两阶段均使用 16 线程。该优化使用 llama.cpp 已有的 `-t` 与 `-tb` 参数，不涉及推理内核源码修改。
