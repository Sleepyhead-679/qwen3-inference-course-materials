# Qwen3 CPU 推理热点分析（2026-11-05）

## 实验条件

模型为 Qwen3-0.6B Q8_0，SHA-256 见 `../sources/model.md`。CPU 为 AMD Ryzen 7 8845H。原始基线见 `raw/20261104T090537Z-2bf03f2e/`，关闭 OpenMP 的结果见 `raw-noomp/20261104T145944Z-65acc4fc/`，逐项比较见 `2026-11-05-noomp-compare.csv`。两次构建的推理源码相同；提交号差异只涉及 `course/qwen3_cpu/` 下的课程脚本。

## CPU 采样

使用 Visual Studio 2022 CPU 使用率工具，采样带符号的 RelWithDebInfo 构建。负载为 `llama-bench -m Q:\Qwen3-0.6B-Q8_0.gguf -p 0 -n 256 -r 10 -ngl 0 -b 2048 -ub 512 -o json`，分别设置 `-t 16` 和 `-t 8`。

- [16 线程采样截图](figures/2026-11-04-tg256-t16.png)：`ggml_vec_dot_q8_0_q8_0` 的自身 CPU 占比为 40.12%；`ggml_barrier` 调用路径的总 CPU 占比为 36.81%，其自身占比为 0.03%。总 CPU 包含被调用函数，不能直接解释为纯等待时间。
- [8 线程采样截图](figures/2026-11-04-tg256-t8.png)：`ggml_vec_dot_q8_0_q8_0` 的自身 CPU 占比为 64.02%。占比变化不能单独用于计算加速比，速度以基准结果为准。

## 分阶段线程配置

相同提示词和 128 个生成 token 下，交替运行 5 轮；原始输出保存在 `raw/2026-11-04-mixed-threads/`。固定 16 线程（`-t 16 -tb 16`）的提示词处理和生成速度中位数分别为 399.2、33.1 token/s；分阶段配置（`-t 8 -tb 16`）分别为 384.6、40.7 token/s。生成速度提升 22.96%，5 轮配对结果均更快。提示词处理两组均使用 16 线程，其读数差异不能归因于线程参数。这里尚未测得完整请求的端到端加速比。

## 关闭 OpenMP 的对照

基线构建为 `GGML_OPENMP=ON`，对照构建为 `GGML_OPENMP=OFF`；其余记录的 GGML 构建选项相同。对照构建的 12 组速度中位数均低于基线。例如，16 线程生成 256 token 从 41.7835 降至 1.30658 token/s；该组 5 次样本范围为 0.558802～17.9885 token/s，波动很大。两套矩阵不在同一时段运行，不能将全部差异精确归因于 OpenMP 开关。本轮不采用关闭 OpenMP 的构建。
